# ADR-0002：动态模型发现与自适应梯队（2026-10-10 更新为 4 档）

## 状态
已接受 & 已实现 - 2026-09-29
2026-10-10 更新：3 档 → 4 档（增加 Ultra）

## 背景
原先网关需要在 config.yaml 手工枚举每个上游模型 ID、API Key 与价格档位，导致三类问题：
1. 目录漂移（配置几天内就过期）；
2. 路由正则规则随厂商改名频繁失效；
3. 运维耗时——逐条复制模型信息。

## 决策
1. **彻底清空 config.yaml 静态段**：
   - 删除全部静态 `providers` / `models`，避免配置漂移。
2. **启动时 100% 动态发现**：
   - `OpenCodeConnector` 启动时自动从 `~/.config/opencode/service.json` 读取凭证；
   - 动态查询 OpenCode REST API 拉取所有活跃模型与价格（7+ 厂商 90+ 模型）。
3. **自适应价格阶梯与能力分层（4 档）**：
   - 零硬编码关键词正则（不写死 `qwen`/`kimi`/`gpt` 等厂商标签）；
   - 纯数据驱动的动态分档：
      - **Lite (≤$0.8/1M)**：低成本档，动态选出最低输入成本者作为该层默认冲锋模型。
      - **Plus ($0.8-$3/1M)**：主力档，中位成本通用模型，选出中位数模型作为默认主力。
      - **Pro ($3-$8/1M)**：思考档，具备 `capabilities.thinkingEffort === true`、带有 `thinking/effort` 参数或 `inputCost >= $3.0`。
      - **Ultra (≥$8/1M)**：旗舰之上档，时长自治 agent 与最难的思考任务（例如 Claude Fable、GPT-5 Ultra）。
4. **认证与调用全代理**：
   - 将所有上游 Provider 注册为 OpenCodeProxyProvider，网关无需持有任何第三方云厂商的 API Key，全链路零秘钥安全直通。

## 后果
- **正向**：
  - 零配置上手：全新 `config.yaml` 启动即发现全部；
  - 目录增量（厂商 SKU、价格波动）下次重启自动生效。
- **负向**：
  - 上游厂商价格变动会在重启时静默改变模型梯队归属；
  - 网关继承 OpenCode daemon REST API 的可用性 / 延迟特性。
