# Project memory — public lessons (committed)

- [2026-09-30] This repo is bun-first: all scripts (build/dev/test) use `bun --filter`; pnpm ignores the root `workspaces` field (no pnpm-workspace.yaml), so `pnpm install` silently skips backend/frontend deps and `pnpm build` fails with TS2307 "Cannot find module 'fastify'/'yaml'/'dotenv'". Use `bun install && bun run build`.
- [2026-09-30] OpenCode user config is two files: provider definitions in ~/.config/opencode/opencode.jsonc under the SINGULAR `provider` node (JSONC — every write must use jsonc-parser text-level modify/applyEdits to preserve comments; plain JSON.parse/stringify destroys a ~2000-line commented file), and credentials in ~/.local/share/opencode/auth.json ({ "<providerID>": { type: 'api', key } | oauth }). All provider CRUD goes through backend/src/opencode/user-config.ts.
- [2026-09-30] Frontend has global ConfirmProvider/ToastProvider (frontend/src/components/) mounted in App.tsx — use `useConfirm()` / `useToast()` hooks for all dialogs and notifications; never add new window.confirm/alert calls.
- [2026-09-30] The backend statically serves frontend/dist (backend/src/routes/console.ts FRONTEND_DIST), so any frontend source change is only visible at http://127.0.0.1:3000 after `bun run build`; `typecheck` alone is not enough, and the gateway process itself does NOT need restarting for frontend-only changes (dist is read from disk per request).
- [2026-09-30] App version is centralized in the root package.json — never hardcode version strings: backend reads it at runtime via backend/src/version.ts (APP_VERSION export; used by CLI banner, --version, daemon info file, /health response), and the frontend gets it injected at build time via Vite define __APP_VERSION__ (declared in frontend/src/vite-env.d.ts, consumed in Layout.tsx). Frontend version changes require `bun run build`; backend requires restart/rebuild since it reads at process start.
- [2026-09-30] `bun run build` runs `tsc -p backend && vite build frontend` — vite does NOT typecheck the frontend; frontend type errors are only caught by `bun run typecheck`.
- [2026-09-30] All fixed-overlay dialogs in this frontend MUST be rendered via createPortal(..., document.body): KeysPage wraps content in `.card` which has `backdrop-filter: blur(16px)`, and non-none backdrop-filter makes an element the containing block for fixed descendants, so a fixed inset:0 overlay rendered inside it centers relative to the card instead of the viewport.
- [2026-09-30] Frontend z-index scale for overlays (keep this gradient when adding new layers): page-level modals 100 (ApiKeysPage), feature dialogs 200 (ProviderModelsDialog list), nested sub-dialogs 210 (its add/edit form), Combobox floating panels 220 (frontend/src/components/Combobox.tsx), global confirm dialog 300 (ConfirmProvider — must sit above ALL feature dialogs), toasts 400 (ToastProvider — always topmost).
- [2026-09-30] ALL frontend dropdowns render through the shared Combobox (frontend/src/components/Combobox.tsx — portal + z-index 220 + ARIA combobox pattern), never native <select>: the native popup listbox is OS-rendered and ignores the 5 custom themes. Filter input auto-appears only when options.length > 8 (FILTER_THRESHOLD).
- [2026-09-30] All modal overlays must lock body scroll while open via useBodyScrollLock(active) from frontend/src/lib/useBodyScrollLock.ts (ref-counted, compensates scrollbar width) — ConfirmProvider, ProviderModelsDialog and ApiKeysPage modals already do; any new dialog must hook it too.
- [2026-09-30] `POST /api/ui/restart` is just `setTimeout(() => process.exit(0), 500)` with NO self-respawn — it only works when the gateway was started by the ocr daemon (sign: ~/.opencode-router dir exists); if the gateway was started manually, calling it kills the service with nothing to bring it back — after using it always poll /health and restart out-of-band (`nohup bun backend/src/index.ts`) if it stays down.
- [2026-09-30] The model edit form exists as two parallel implementations — ProviderModelsDialog.tsx nested add/edit form (provider page) and ModelEditDialog.tsx (/models page); both build the same PATCH payload for updateProviderModel, so any new form field or save-payload change must be mirrored in BOTH files (or the forms should be extracted into a shared component).
- [2026-09-30] All list pagination renders through the shared Pagination component (frontend/src/components/Pagination.tsx): callers pass page/pageSize/total/onChange — server-side pages (SessionsPage, LogsPage, CapturesPage) re-fetch in onChange, client-side pages (ModelsPage/ApiKeysPage/GuardrailsPage) re-slice; never add data fetching to the component. Page-size ladder is uniformly [10,20,50,100,200]; the bar renders whenever the list is non-empty — summary text alone on the left, controls (size selector + page buttons, selector first) grouped on the right; buttons show even on a single page (disabled "‹ 1 ›"), and the bar returns null only when total = 0.
- [2026-09-30] Theme-dependent colors in this frontend must come from CSS variables in frontend/src/styles/index.css (per data-theme block) — never hardcode dark rgba values (e.g. rgba(9,9,11,…)) in TSX inline styles, or they persist in the light theme; when adding a new theme color, define it for ALL 5 themes (obsidian/indigo/cyber/sunset/light).
- [2026-10-07] Frontend fonts are fully self-hosted via @fontsource (Inter/JetBrains Mono/Noto Sans SC imported per-weight in frontend/src/main.tsx; no external CDN — must stay that way for offline/intranet/mainland-China use). To add a font weight or family: `bun add @fontsource/<family>` then import the weight CSS in main.tsx; font-family stacks live in frontend/src/styles/index.css and must end with generic CJK fallbacks (Noto Sans SC/Microsoft YaHei/sans-serif).
- [2026-10-07] ~/.opencode-router dir existing is NOT proof the daemon manages the gateway — on 2026-10-07 POST /api/ui/restart killed the process with no respawn despite the dir existing; always poll /health after restart and start out-of-band (`bun backend/src/index.ts` in background) if it stays down, and prefer asking the user how the gateway is managed before restarting.
- [2026-10-07] Backend has NO config hot-reload: Orchestrator snapshots this.config at construction (orchestrator.ts:38), so config.yaml changes (rules/budget/classifier/fallback etc.) only affect routing after a gateway restart — even though SettingsPage's button says "保存配置并热加载"; only frontend dist changes are hot (read from disk per request).
- [2026-10-07] Theme system now standardizes on 10 shared visual tokens (--card-shadow/-hover, --btn-bg/-hover, --btn-primary-text/-shadow/-shadow-hover, --focus-ring, --scrollbar-thumb/-hover) that MUST be defined in every [data-theme] block in frontend/src/styles/index.css; visual language is soft shadow + hairline border + inset top highlight + 4% SVG noise in --bg-gradient (light theme: 3% noise, neutral slate shadows, white primary-button text) — do not reintroduce colored neon glow box-shadows.
